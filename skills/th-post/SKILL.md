# th-post

아이디어 하나를 누군가 끝까지 읽는 쓰레드 글로 만든다. (원본 `ig-reel` + `ig-caption`)

이 폴더의 도구 두 개는 실제로 돌아간다. 쓴다. 첫 줄을 눈대중으로 보지 않고, 길이를 짐작하지 않는다.

```bash
python3 hookscore.py hooks.txt          # 첫 줄 후보 순위 (한 줄에 하나)
python3 hookscore.py --hook "한 줄"      # 하나만 채점
python3 chain.py draft.txt              # 붙여넣기 전 검사 (연결글은 --- 줄로 나눔)
python3 chain.py draft.txt --strict     # 이모지를 더 크게 세는 보수적 계산
```

## 쓰기 전에

1. `~/.claude/threads/voice.md` 가 있으면 읽는다. 사용자의 말투 파일이다: 어떻게 말하는지,
   절대 안 쓰는 말, 누구에게 말하는지. 없으면 **사용자가 쓴 글 3개**를 받아 읽고, 말투를
   뽑아서 파일을 쓴다(`/th-voice`). 말투가 틀린 글은 쓸 수 없다. 사용자 이름으로 올라가기 때문이다.
2. 이 폴더의 `hooks.json` 을 읽는다. 공식 26개, 각각 틀·채운 예시·어디에 좋은지·어떻게 망가지는지.
3. 아이디어가 얇으면 부풀리지 않는다. 한 번에 묶어서 묻는다: 무슨 일이 있었고, 누구에게,
   무엇을 잃었거나 얻었나. 글 하나에는 구체적인 사실 하나가 필요하다. 쓰기 전에 받는다.
4. `~/.claude/threads/swipe.md` 가 있으면 읽는다. `/th-viral` 이 쓰는 파일이고, 지금 사용자 분야에서
   어떤 공식이 먹히는지에 대한 사용자 자신의 증거다. 이 파일의 기본값보다 우선한다.

## 모양

쓰레드 글은 첫 줄에서 결정되고 그다음 두 줄에서 붙잡힌다.

```
첫 줄      훅. 주장. 피드에서 이 줄만 보이고 나머지는 접힐 수 있다. 인사·서론 금지.
둘째 줄    왜 읽는 사람과 상관있는지. 한 줄.
본문       한 문단에 생각 하나. 문단 사이 빈 줄.
끝         훅이 약속한 걸 준다. 그리고 부탁 하나(답글, 저장, 팔로우 중 하나).
마지막 줄  첫 줄의 단어 하나를 다시 쓴다. 다시 읽을 때 깔끔하게 닫힌다.
```

길이: 단독 글 하나는 500자까지다. 대부분은 150~350자면 충분하다. 넘치면 억지로 줄이지 말고
연결글(3~6개)로 나눈다. 연결글은 1번 글만 봐도 읽을 이유가 있어야 한다.

## 순서

**1. 첫 줄 후보 셋.** 아이디어를 `hooks.json` 에 대보고, 진짜 맞는 공식 셋을 골라 하나씩 쓴다.
한 문장을 세 번 바꿔 쓰는 게 아니라 서로 다른 공식이어야 한다.

**2. 채점.** 세 줄을 한 줄에 하나씩 파일에 넣고 `hookscore.py` 를 돌려 순위를 보여준다.
1등이 50점 아래면 아직 훅이 없다. 다듬어서 고쳐지지 않는다.

**3. 본문.** 1등 훅으로 쓴다. 사용자가 실제로 말하는 대로. 짧은 문장. 두 번 읽어야 하는 문장 없이.

**4. 검사.** `chain.py draft.txt` 를 돌린다. FAIL은 전부 고친다: 500자 초과, 주제 태그 2개 이상.
깨끗해질 때까지 다시 돌린다. WARN(1번 글의 링크, 연결글 번호 어긋남, `---` 없이 번호만 붙인 연결글,
닫히지 않은 코드 블록, 이모지 과다, 긴 덩어리)은 고칠지 말지 소리 내서 정한다.

**5. 사람 말로.** 보여주기 전에 `/th-human` 을 돌린다. 쓰레드는 글이 짧아서 상투어 하나가 차지하는
비중이 크다.

**6. 보여준다.** 붙여넣기 좋게 코드 블록으로(연결글은 글마다 따로), 그리고:

```
POST READY
훅:       #5 시간 압축 · 66점 OK
형식:     단독 글 · 212자
태그:     #프론트엔드 (1개)
사람다움: 상투어 2개 지움, 79 PASS
검사:     READY

"좋아"라고 하면 기록해 둘게요. 고칠 곳이 있으면 말해주세요.
```

**7. 올리지 않는다.** 이 스킬은 글만 쓴다. 올리는 건 사용자다. "좋아"라고 하면
`~/.claude/threads/log.md` 에 날짜, 훅 공식, 첫 줄을 덧붙인다. 나중에 `/th-audit` 가 이 기록을 쓴다.

## 쓰레드에서 붙이는 것 (원본 ig-caption에서 가져온 규칙)

- **주제 태그는 글 하나에 하나.** 쓰레드는 태그를 하나만 붙인다. 원본의 '해시태그 5개 이하,
  주제 이름표로'와 같은 생각이다. `#인기`, `#추천` 같은 아무것도 말하지 않는 태그는 뺀다.
- **검색어는 문장 안에.** 찾아지고 싶은 말은 사람이 칠 법한 말 그대로 본문에 넣는다.
- **1번 글에 링크를 넣지 않는다.** 읽기 전에 나간다. 링크는 마지막 연결글이나 첫 답글에 단다.
  그렇게 했으면 영수증에 적는다.
- **부탁은 하나.** 둘이면 없는 것과 같다.
- **이모지는 문장부호로, 장식이 아니라.** `chain.py` 가 많으면 표시한다.
- **이미지를 붙이면 대체 텍스트를 쓴다.** 20초면 된다.

## 차이를 만드는 규칙

- **글 하나에 생각 하나.** 생각이 둘이면 글이 둘이다. 그렇게 말한다.
- **형용사보다 숫자.** "40만 원"이 "많이"를 이긴다. 사용자가 숫자를 안 줬으면 구멍을 피해 쓰지 말고 묻는다.
- **서론을 자른다.** 인사, "오늘은 ~에 대해", 이름, 자기소개 없이. 글은 보통 셋째 문장에서 시작한다.
- **문단마다 바뀐다.** 같은 말을 두 문단에 걸쳐 하면 거기서 나간다.
- **끝에 부탁 하나.** 답글, 저장, 팔로우 중 하나.
- **절대 지어내지 않는다.** 사용자 이름으로 된 가짜 숫자·고객·매출·결과를 만들지 않는다. 자리표시로도.
  숫자가 필요한데 모르면 `{{내 숫자}}` 를 남기고 표시한다.

## 예시

```
/th-post 제안서 쓰는 시간을 템플릿 하나로 5시간에서 20분으로 줄였음
```

```
훅 (채점)
  66  OK      #5  시간 압축  "제안서 하나에 다섯 시간 걸렸는데, 이제 20분이면 끝난다."
  60  OK      #1  비용 고백  "2년 동안 매주 네 시간을 서식 맞추는 데 썼다."
  37  WEAK    #9  가져가세요 "그대로 가져가세요. 그걸 해낸 제안서 템플릿이에요."

#5로 간다. 비율이 믿기고, 한눈에 읽히고, 숫자가 사용자 것이다.
```

| 원본 | 여기 | 이유 |
| --- | --- | --- |
