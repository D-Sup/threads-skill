# th-post

아이디어 하나를 끝까지 읽히는 쓰레드 글로 만든다.

이 폴더의 도구 두 개는 실제로 돌아간다. 눈대중으로 판단하지 말고 돌린다.

```bash
python3 hookscore.py hooks.txt          # 첫 줄 후보 순위 (한 줄에 하나)
python3 hookscore.py --hook "한 줄"      # 하나만 채점
python3 chain.py draft.txt              # 붙여넣기 전 검사 (연결글은 --- 줄로 나눔)
python3 chain.py draft.txt --strict     # 이모지를 더 크게 세는 보수적 계산
```

## 쓰기 전에

1. `~/.claude/threads/voice.md` 를 읽는다. 없으면 `/th-voice` 부터 한다.
   말투가 틀린 초안은 쓸 수 없다.
2. 이 폴더의 `hooks.json` 을 읽는다. 공식 22개, 각각 틀·예시·어디에 좋은지·망치는 법.
3. `~/.claude/threads/swipe.md` 가 있으면 읽는다. `/th-viral` 이 만든 '내 분야에서
   지금 먹히는 공식' 기록이고, 기본값보다 우선한다.
4. `~/.claude/threads/log.md` 가 있으면 최근 2주 첫 줄과 공식을 보고 겹치지 않게 한다.
5. 아이디어가 얇으면 부풀리지 않는다. 한 번에 묻는다: 무슨 일이 있었고, 누구에게,
   무엇을 잃었거나 얻었나. 글 하나에는 구체적인 사실 하나가 필요하다.
   자료(링크·문서·뉴스)를 정리하는 글이면 `/th-source` 를 쓴다.

## 단독 글이냐 연결글이냐

- **단독 글:** 주장 하나, 팁 하나, 이야기 한 장면. 500자 안에서 끝난다. 기본은 이것.
- **연결글:** 단계·목록·이야기처럼 나눠야 읽기 좋을 때. 3~6개. 1번 글만 봐도
  읽을 이유가 있어야 하고, 각 글은 앞 글 없이도 대충 이해돼야 한다.
- 500자에 억지로 꾸겨 넣지 않는다. 넘치면 연결글로 나누거나 덜어낸다.

## 모양

```
첫 줄      훅. 피드에서 이것만 보고 넘길지 정한다. 인사·서론 금지.
둘째 줄    왜 읽는 사람과 상관있는지. 한 줄.
본문       한 문단에 생각 하나. 문단 사이 빈 줄. 숫자를 쓴다.
끝         약속한 걸 준다. 그리고 부탁은 하나만, 또는 없음.
           (질문으로 끝내면 답글이 붙는다. 쓰레드에서 답글이 가장 큰 신호다.)
태그       주제 태그는 글 하나에 하나만 붙는다. 1번 글에.
```

## 순서

**1. 첫 줄 후보 셋.** `hooks.json` 에서 아이디어에 진짜 맞는 공식 셋을 골라 하나씩
쓴다. 한 문장을 세 번 바꿔 쓰는 게 아니라 서로 다른 공식이어야 한다.

**2. 채점.** 세 줄을 파일에 넣고 `hookscore.py` 를 돌려 순위를 보여준다.
1등이 50점 아래면 아직 훅이 없다. 다듬어서 안 되고 아이디어를 다시 본다.

**3. 본문.** 1등 훅으로 쓴다. voice.md 말투 그대로. 짧은 문장, 다시 읽어야 하는 문장 없이.

**4. 사람 말로.** `/th-human` 의 humanize.py와 detect.py를 돌린다. AI 티가 나면
쓰레드에서는 바로 넘겨진다.

**5. 검사.** `chain.py` 를 돌려 FAIL을 전부 고친다. WARN은 고칠지 말지 이유를 말한다.

**6. 보여준다.** 붙여넣기 좋게 코드 블록으로(연결글은 글마다 따로), 그리고:

```
POST READY
형식:     연결글 3개 · 총 642자
훅:       #1 비용 고백 · 81점 STRONG
태그:     #프론트엔드 (1번 글)
사람다움: 79 PASS (상투어 2개 지움)
검사:     READY

"좋아"라고 하면 기록해 둘게요. 고칠 곳이 있으면 말해주세요.
```

**7. 올리지 않는다.** 이 스킬은 글만 쓴다. 올리는 건 사용자가 한다.
"좋아"라고 하면 `~/.claude/threads/log.md` 에 날짜, 공식 번호, 첫 줄, 형식을 한 줄 덧붙인다.
나중에 `/th-audit` 가 이 기록을 쓴다.

## 지켜야 할 것

- **글 하나에 생각 하나.** 두 개면 글 두 개다. 그렇게 말한다.
- **형용사보다 숫자.** 숫자가 없으면 지어내지 말고 묻는다.
- **절대 지어내지 않는다.** 사용자 이름으로 된 가짜 숫자·고객·매출·경험을 만들지 않는다.
  필요하면 `{{내 숫자}}` 로 비워 두고 표시한다.
- **서론을 자른다.** 인사, "오늘은 ~에 대해", 자기소개 없이 핵심부터.
- **낚시 금지.** "충격", "이거 모르면 손해"는 한 번은 먹혀도 계정 신뢰를 깎는다.
- **남의 글을 베끼지 않는다.** 구조는 빌려도 문장과 경험은 사용자 것이어야 한다.
- **링크는 마지막 글이나 답글로.** 1번 글에 링크가 있으면 읽기 전에 나간다.

## 예시

```
/th-post 레거시 프로젝트 빌드가 12분에서 2분으로 줄었는데 원인이 소스맵 설정이었음
```

```
훅 (채점)
  84  STRONG  #5  시간 압축  "빌드 12분 걸리던 게 2분 됐다. 바꾼 건 설정 한 줄."
  81  STRONG  #1  비용 고백  "1년 동안 하루 10분씩 날린 이유가 소스맵 설정이었다."
  63  OK      #9  가져가세요 "그대로 복사해서 쓰세요. 빌드 10분 줄인 설정."

#5로 간다. 숫자 두 개가 한눈에 읽히고, 직접 겪은 일이다.
```

다른 분야 예:
- 카페: `/th-post 아이스 음료 가격 500원 올렸는데 매출이 오히려 늘었음`
- 육아: `/th-post 수면 교육 3주 해본 기록, 첫 주는 완전 실패`
