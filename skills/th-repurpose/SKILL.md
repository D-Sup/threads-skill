# th-repurpose

좋은 긴 자료 하나에는 글 다섯 개가 들어 있다. 대부분 하나만 꺼내고 나머지를 버린다.

## 입력

자막, 글, 뉴스레터, 대본, 회의 요약, 발표 자료. URL을 주면 이 세션의 도구(자막 추출,
웹 읽기)로 원문을 가져오고, 안 되면 붙여넣어 달라고 한다. 꺼내기 전에 전부 읽는다.

남의 자료라면 요약과 내 생각으로 쓰고, 출처를 단다. `/th-source` 규칙을 따른다.

## 요약하지 말고 꺼낸다

영상 요약은 쓰레드 글이 아니다. 아무도 요약을 원하지 않는다. 혼자서도 서는 것들을 꺼낸다:

| 꺼낼 것 | 무엇 |
| --- | --- |
| **주장** | 논쟁을 일으킬 문장 전부 |
| **숫자** | 금액, 기간, 비율 전부 |
| **이야기** | 사람·장면·대가가 있는 순간 전부 |
| **원리** | "실제로는 이렇게 돌아간다" 전부 |
| **실수** | 잘못된 걸 인정한 순간 전부 |
| **한 줄** | 그대로 인용할 만한 문장 전부 |

쓰기 전에 찾은 것을 개수와 함께 먼저 보여준다. 네 개가 안 되면 얇은 자료다.
억지로 다섯 개를 짜내면 다섯 개 다 얇다. 그렇게 말한다.

## 꺼낸 것마다 형식

- **주장, 실수, 한 줄** → 단독 글
- **원리, 목록, 단계** → 연결글
- **이야기** → 연결글 (1번 = 장면, 마지막 = 대가와 배운 것)

## 일주일로

꺼낸 것 하나가 글 하나다. 각 글은 완전히 혼자 선다. 읽는 사람은 원본을 안 봤고 앞으로도
안 본다. "지난번 영상에서 말했듯" 같은 말은 쓰지 않는다. 그 글이 전부다.

각각 `th-post/hooks.json` 공식을 다르게 붙인다. 한 자료에서 나온 다섯 개가 같은 첫 줄
모양이면 공장처럼 읽힌다. 실제로 공장이라서.

순서: 가장 센 주장을 먼저, 이야기를 주 중간, 원리를 마지막에 (앞 글을 좋아한 사람이
그걸 기다릴 때).

`voice.md` 의 하루 개수에 맞춘다. 하루 1~2개면 자료 하나로 3~5일.

## 보여줄 것

```
자료: "디자인 시스템 3년 운영 회고" (블로그, 6,200자)

찾은 것  주장 4, 숫자 7, 이야기 2, 원리 3, 실수 2, 한 줄 5

계획
월  단독  #20 통념 뒤집기   "컴포넌트 많을수록 좋은 디자인 시스템이 아니다"
화  연결  #11 숫자 목록     토큰 이름 정할 때 지킨 규칙 4개
수  연결  #22 장면부터      버튼 하나 바꿨다가 화면 140개 깨진 날
금  단독  #1  비용 고백     문서화 안 해서 같은 질문에 쓴 시간 주 5시간

"월요일 거 써줘"라고 하면 쓸게요.
```

그다음 요청받을 때마다 하나씩 `/th-post` 와 `/th-human` 을 거쳐 쓴다. 다섯 개를
한꺼번에 완성해서 내놓지 않는다. 다 같은 말투가 되고, 하나도 안 올라간다.
