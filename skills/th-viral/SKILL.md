# th-viral

조사 스킬이다. 이 묶음의 나머지는 쓰고, 이건 보러 간다. 매일 말고 한 달에 한 번 돌린다.
공식은 한 철 간다.

이 폴더의 도구 하나는 실제로 돌아간다:

```bash
python3 rank.py captured.tsv --out ~/.claude/threads/swipe.md
```

## 이 스킬을 할 가치가 있게 만드는 한 가지

**조회수 자체는 증거가 아니다.** 팔로워 200만 계정의 조회수 40만은 조용한 화요일이다.
팔로워 4천 계정의 조회수 40만은 뭔가를 찾은 거고, 그 뭔가는 따라 할 수 있다.

그래서 여기서는 전부 **배수**로 순위를 낸다: 조회수 ÷ 그 계정 최근 글 조회수 중앙값.
3배 넘으면 신호다. 1.5배 아래는 그 계정의 평범한 날이고, 숫자가 아무리 커 보여도 배울 게 없다.

계정은 **사용자 크기의 10배 안쪽**에서 모은다. 팔로워 200만에서 먹히는 공식은 200만이라서 먹히는 경우가 많다.

쓰레드는 남의 글 조회수도 글을 누르면 보인다. 조회수가 안 보이는 글은 좋아요로 대신 계산하고, 덜 정확하다고 표시한다.

## 1단계: 계정 고르기

사용자에게 6~12개를 받거나, 제안하고 승인받는다:

- **4개 직접:** 같은 분야, 같은 제안, 조금 앞선 계정.
- **4개 옆 분야:** 분야는 다르고 독자는 같은 계정. 분야 안의 누구보다 먼저 형식을 빌려 오는 곳이다.
- **2~4개 큰 계정:** 훨씬 큰 계정. 형식만 보고, 올리는 속도나 말투는 절대 따라 하지 않는다.

사용자에게 **저장한 글 목록**도 열어보게 한다. 가장 빠르고 가장 관련 있는 자료이고, 이미 사용자 취향으로 걸러져 있다.

## 2단계: 보러 가기

이 세션에 실제로 있는 브라우징 도구를 쓴다: 앱 안 브라우저, 사용자 크롬에 붙는 확장, 컴퓨터 사용 도구.
양이 사람이 읽을 만큼 적어서, API가 없어도 되고 필요하지도 않다.

**어길 수 없는 규칙:**

- **사용자 대신 쓰레드에 로그인하지 않고, 비밀번호를 묻지 않는다.** 로그인이 필요하면 이미 로그인한 건
  사용자다. 사용자가 있을 때 사용자 브라우저를 같이 쓰거나, 붙여넣어 달라고 한다.
- **긁어 가기가 아니라 읽기다.** 계정 10개, 글 10여 개씩, 사람 속도로. 대량 자동 수집은 Meta 약관 위반이고
  계정이 막힌다. 크롤러를 만들지 않고, 수집 서비스를 쓰지 않고, 백그라운드로 반복하지 않는다.
- **공식을 따라 하지, 글을 베끼지 않는다.** 첫 줄의 모양, 구조, 길이, 연결글로 나누는 방식. 그 사람의 문장,
  말투, 경험은 아니다. 스와이프 파일의 모든 줄에 출처 계정을 붙인다.

**글마다 적을 것**, 쓴 사람 말 그대로:

| 칸 | 설명 |
| --- | --- |
| account | 핸들 |
| followers | 프로필에서 |
| median | 최근 글 12개를 훑어보고 가운데 조회수 |
| views | 이 글 ('4.1만'처럼 적어도 된다) |
| hook | 첫 줄, 맞춤법 틀린 것까지 원문 그대로 |
| format | 단독 / 연결글 몇 개 / 이미지 |
| length | 첫 글 글자 수 |
| cta | 끝에 무엇을 부탁했나 |

median이 가장 중요하다. 이게 없으면 다시 팔로워 순위로 돌아가고, 그걸 막으려고 이 스킬이 있다.

**쓰레드가 충분히 안 보여줄 때:** 같은 첫 줄 문법은 유튜브 쇼츠에서도 돈다. 쇼츠는 조회수와 자막이
로그인 없이 공개라 정당한 두 번째 자료다. 말로 한 훅이지만 첫 문장의 모양은 같다:

```bash
# 채널 쇼츠 조회수
python3 -m yt_dlp --flat-playlist --playlist-end 40 -J \
  "https://www.youtube.com/@HANDLE/shorts" > channel.json

# 쇼츠 하나의 첫 문장, 자동 자막에서
python3 -m yt_dlp --skip-download --write-auto-subs --sub-langs "ko.*" \
  --sub-format json3 -o hook "https://www.youtube.com/watch?v=VIDEO_ID"
```

시간 표시가 3.0초 아래인 자막 단어를 전부 모은다. 그게 쓴 대로가 아니라 말한 대로의 훅이다.

공식 Threads API의 키워드 검색은 남의 공개 글을 보려면 Meta 앱 심사가 필요하다. 심사를 받은 사용자만 쓴다.

## 3단계: 순위

머리글 줄이 있는 탭 구분 파일을 채우고 스크립트를 돌린다:

```
account	followers	median	views	hook
@someone	4800	1100	4.1만	아무도 안 알려주는데, 첫 글 30개는 반응 없는 게 정상이에요
```

```bash
python3 rank.py captured.tsv --out ~/.claude/threads/swipe.md
```

배수를 계산하고, `/th-post` 가 쓰는 것과 같은 공식 26개로 훅 이름을 붙이고, `hookscore.py` 로 훅마다 점수를 매기고,
위 1/3과 아래 1/3을 가르는 것을 보여준다.

## 4단계: 무슨 뜻인지, 조심해서

세 가지만, 그 이상은 말하지 않는다:

1. **위 1/3에 몰린 공식**, 개수와 함께. 계정 6개에 걸쳐 두 공식이 각각 네 번씩 나오면 발견이다. 한 번 두 번은 아니다.
2. **위 1/3이 아래 1/3과 달리 구조적으로 가진 것:** 첫 줄 길이, 숫자가 있는지, 연결글인지, 이미지가 있는지, 부탁이 어디 있는지.
3. **분류 안 된 줄.** 분류기가 이름 붙이지 못한 첫 줄은 소음이거나 `hooks.json` 에 아직 없는 공식이다. 직접 읽는다.
   출력에서 가장 값진 칸이고, 스크립트가 그 개수를 찍는 이유다.

그리고 표본 크기와 신뢰도를 쉬운 말로 밝힌다. 계정 6개에 글 40개면 주장할 만하다. 12개면 아니다.
그걸 말하는 게 조사와 별자리 운세의 차이다.

## 5단계: 쓸 수 있는 것으로

위 공식 셋마다 **사용자의 버전**을 쓴다: 사용자 이야기, 사용자 숫자로, 지금 먹히는 모양에 담아서.
공식 번호를 정해서 `/th-post` 로 넘긴다.

"이 글처럼 써보세요"를 돌려주지 않는다. 내일 바로 쓸 수 있는 첫 줄을 돌려준다.

## 보여줄 것

```
SWIPE  ·  글 38개  ·  계정 7개  ·  기준: 계정 중앙값

OUTLIERS (3배 넘음)
  38.4x  훅 86  #3  아무도 안 알려주는   @acct_a    4.1만  (중앙값 1,070)
  11.2x  훅 79  #9  그대로 가져가세요    @acct_c    1.8만  (중앙값 1,610)
  ...

몰린 것
  #3 아무도 안 알려주는   위 1/3에 5번, 아래 0번
  #2 하지 마세요           4번
  첫 줄 길이 중앙값        위 18자, 아래 41자

분류 안 됨 (6)
  둘이 같은 모양인데 hooks.json에 없다: 남의 답글을 첫 줄로 그대로 인용하는 훅. 추가할 만하다.

내 버전
  #3  "아무도 안 알려주는데, 첫 제안서 20개는 떨어지는 게 정상이에요."
  ...
```

`~/.claude/threads/swipe.md` 에 쓴다. `/th-post` 와 `/th-plan` 이 둘 다 이 파일을 읽는다. 그게 핵심이다.
한 번 돌리고 나면, 묶음의 나머지가 기본값 대신 사용자 자신의 증거로 일한다.

이 스킬은 아무것도 올리지 않고, 팔로우·좋아요·메시지도 하지 않는다. 읽기만 한다.
