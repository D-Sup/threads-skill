# th-source

하루 한두 개라도 '저장할 만한' 글을 올리고 싶을 때 쓴다. 소식을 옮기기만 하는
계정은 많다. 이 스킬은 두 가지를 더한다. **원문과 맞는지 확인한 사실**과
**내 판단 한 줄**이다.

## 입력

- 링크(URL), 붙여넣은 글, PDF, 스크린샷, 내 커밋·작업 메모
- URL은 이 세션에 있는 도구(웹 읽기, 브라우저)로 원문을 연다. 열 수 없으면
  붙여넣어 달라고 한다. 요약본이나 남의 정리 글만 보고 쓰지 않는다.

## 순서

**1. 원문을 끝까지 읽는다.** 제목·첫 문단만 보고 쓰지 않는다.

**2. 사실 카드를 만든다.** 글에 쓸 사실마다:

```
사실                       원문 위치/인용                     확인
출시일 11월 12일            "available starting Nov 12"       원문 일치
무료 요금제 하루 20회        요금 페이지 표                      원문 일치
"속도 2배"                 회사 블로그 주장, 독립 측정 없음        주장으로만 표기
```

- 숫자·날짜·이름·가격은 하나씩 원문과 대조한다.
- 회사가 스스로 한 주장은 "~라고 밝혔다"로 쓴다. 사실처럼 쓰지 않는다.
- 원문에 없는 건 쓰지 않는다. 궁금하면 사용자에게 묻거나 "확인 못 함"으로 둔다.
- 2차 출처(다른 사람 정리 글, 커뮤니티)만 있으면 그렇다고 밝힌다.

**3. '그래서 나한테 뭐가 달라지나'를 찾는다.** voice.md의 독자에게 이 소식이
무슨 뜻인지 한 줄. 이게 다른 계정과 갈리는 부분이다. 사용자 경험·의견이 있으면
그걸 쓰고, 없으면 묻는다. 지어내지 않는다.

**4. 형식을 고른다.**
- 핵심 3줄 단독 글: 빠른 소식
- 연결글: 1번 = 훅 + 한 줄 요약, 2~4번 = 사실 하나씩, 마지막 = 내 판단 + 출처 링크
- 튜토리얼형: 1번 = 무엇을 할 수 있게 되나, 그다음 단계별

**5. `/th-post` 의 순서대로 쓴다.** 훅 셋 → `hookscore.py` → 본문 → `/th-human` → `chain.py`.
훅 공식은 #24 새로 나온 것, #19 마감이 있는 변화, #23 놀라운 통계, #17 직접 비교가 잘 맞는다.

**6. 출처를 붙인다.** 마지막 글 또는 첫 답글에 원문 링크. 1번 글에는 넣지 않는다.

## 보여줄 것

```
SOURCE READY
원문:     Google 블로그 (2026-11-12), 요금 페이지
사실:     6개 확인, 1개 '회사 주장'으로 표기, 0개 지어냄
내 판단:  "무료로 써볼 사람은 하루 20회 제한부터 확인" (사용자 의견)
형식:     연결글 4개 · 훅 #24 · 78점
출처:     4번 글 끝에 링크
```

그리고 사실 카드 표를 같이 보여준다. 사용자가 확인할 수 있게.

## 지켜야 할 것

- **원문에 없는 숫자는 0개.** 이 스킬이 존재하는 이유다.
- **틀렸으면 정정 글을 쓴다.** 올린 뒤 틀린 게 보이면 숨기지 말고 정정하는 글을 같이 쓴다.
- **남의 글·기사를 통째로 옮기지 않는다.** 요약하고 인용은 짧게, 출처를 단다.
- **루머는 루머라고 쓴다.** 유출·소문은 출처와 함께 "확인되지 않음"을 붙인다.
- 의료·금융·법률처럼 조언이 위험한 분야는 정보만 전하고 조언처럼 쓰지 않는다.

## 예시

```
/th-source https://example.com/release-notes 이거 프론트 개발자 입장에서 정리해줘
/th-source 오늘 한 작업 (커밋 로그 붙여넣음) 이거 배운 점 위주로
/th-source 동네 상권 지원금 공고문(PDF) 사장님들이 알아야 할 것만
```

## 원본과 다른 점

원본에 없는 스킬이다. 쓰레드에서 소식·문서 정리 글이 많이 올라와서 더했다. 지우면 나머지 10개는 그대로 돈다.
